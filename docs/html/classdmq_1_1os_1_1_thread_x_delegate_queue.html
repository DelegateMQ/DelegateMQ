Create the underlying HIGH and NORMAL queues, each with room for 'capacity' pointers, plus the counting semaphore doorbell (initial count 0).

Parameters
nameQueue/semaphore name; ThreadX stores this pointer, not a copy, so it must outlive the queue (callers pass THREAD_NAME.c_str(), which lives as long as the owning Thread). The same name is shared across both queues and the semaphore – ThreadX names are purely informational for kernel-aware debuggers and need not be unique.

◆ Receive()

ThreadMsg * dmq::os::ThreadXDelegateQueue::Receive ( ULONG waitOption)
inline

Receive a message pointer, blocking up to 'waitOption'. The HIGH lane is always checked – and drained – first, so a pending HIGH message is returned even if NORMAL messages arrived earlier. Blocks on the doorbell semaphore (the single native wait), then does a non-blocking pop from whichever lane has data; the semaphore count guarantees at least one lane is non-empty once the get succeeds.

Returns
the message, or nullptr on timeout.

◆ Send()

bool dmq::os::ThreadXDelegateQueue::Send ( ThreadMsg * msg,
bool highPriority,
ULONG waitOption )
inline

Send a message pointer. 'highPriority' routes to the HIGH lane, which Receive() always drains first; otherwise the NORMAL lane. Both lanes are always pushed to the BACK – see the file-level comment for why "send to front" must never be reintroduced here. 'waitOption' is TX_NO_WAIT for non-blocking, TX_WAIT_FOREVER to block forever, or a finite tick count for a bounded wait; it applies only to the queue push (each lane has its own independent capacity – there is no combined-depth wait across both). Putting the doorbell semaphore never blocks and cannot realistically fail (only on ULONG overflow, far beyond any real combined lane capacity).

Returns
true if the message was enqueued.
