Detailed Description

Generic multi-peer DataBus network node for any ITransport type.

See also
https://github.com/DelegateMQ/DelegateMQ David Lafreniere, 2025.

NetworkNode wraps the full DataBus networking plumbing — transport setup, Participant creation, reliability stacking, receive-loop thread — behind a five-method API. A new user brings up a multi-process distributed DataBus system by writing only a SetupNetwork() function:

// In your node's System.cpp:
void System::SetupNetwork() {
m_network.Start("GUI", 5010);
m_network.Receive<HeartbeatMsg>(topics::SAFETY_HB, RID_SAFETY_HB, serHB);
m_network.Receive<FaultMsg> (topics::FAULT, RID_FAULT, serFault);
m_network.AddPeer("Safety", "127.0.0.1", 5013);
m_network.Send<HeartbeatMsg>(topics::GUI_HB, RID_GUI_HB, serHB);
m_network.Send<FaultMsg> (topics::FAULT, RID_FAULT, serFault,
dmq::databus::Reliability::RELIABLE);
}
// From here, use DataBus::Subscribe / DataBus::Publish normally.
dmq::databus::Reliability::RELIABLE
@ RELIABLE
Transport send with ACK and automatic retry (RetryMonitor stack).

Topic ordering: Receive() and Send() may be called before or after Start() / AddPeer() in any order. NetworkNode defers registration and applies it retroactively when the participant is created.

Template Parameters
TransportAny ITransport-derived class with a nested Type enum providing Type::PUB (sender) and Type::SUB (receiver).
MaxPeersMaximum remote peers (fixed allocation, default 4).
MaxTopicsMaximum in- or out-topics each (fixed, default 16).
